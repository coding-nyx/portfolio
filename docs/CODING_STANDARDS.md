# Coding principles: applied and remaining

This review describes controls implemented in this refactor. It does not claim that formatting, a folder reorganization or passing tests makes every part of the project production-perfect.

## Applied principles and enforcement

| Principle                           | Implementation and evidence                                                                                                                                                                                                   |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cohesion and single responsibility  | App composition, feature views/hooks/models, shared UI/preferences, client services and server adapters have distinct owners. The chapter collection and HTTP handler no longer carry unrelated responsibilities in one file. |
| Directed dependencies               | ESLint rejects feature-to-feature imports, UI imports into services/data, reversed shared dependencies, unresolved relative paths and missing extensions. Source regression checks cover reachability and cycles.             |
| Separation of effects and rendering | Contact and Rook state/request handling live in hooks. Chapter DOM navigation lives in the app. Services emit callbacks rather than controlling views.                                                                        |
| Shared contracts and content        | Rook limits/endpoint are defined once for both runtimes. Portfolio facts remain shared public data. Pure skill/timeline/form logic is separate from views.                                                                    |
| Explicit failure behavior           | Bounded server validation and sanitized errors; labeled Rook fallback; cancellation propagation; contact delivery requires configuration and a successful send. Optional chunk failure has a local boundary.                  |
| Resource ownership                  | Request abort controllers, native-dialog focus restoration, listener/observer cleanup, scheduled-work cancellation and WebGL disposal belong to their owning feature/runtime.                                                 |
| Consistent code and naming          | Prettier, EditorConfig, semantic component names, strict equality, `const` preference, no unused bindings and JSX undefined-reference checks. Unused uppercase imports are no longer exempt from lint.                        |
| Hook discipline                     | React Hooks lint rules are enforced. Context values/callbacks are stabilized where they are shared; hooks reject use outside their provider.                                                                                  |
| Optional code stays optional        | Lazy Rook, island/Three.js, EmailJS and idle analytics; smaller `m`/`domAnimation` motion usage; manifest-based UI startup budgets.                                                                                           |
| Regression relevance                | Tests referring only to removed components/helpers were retired or redirected to active features. Existing public-claims and API tests remain. No scratch test/prototype files were added.                                    |
| Repeatable workflow                 | npm is authoritative; one package lockfile and Node 22 version declaration match CI. `npm run check` includes formatting, lint, regressions, production build and content/bundle audits.                                      |
| Future maintenance                  | `AGENTS.md` records project rules. Architecture, API behavior and this remaining-gap review are documented together.                                                                                                          |

## Not yet fully enforced or completed

| Area                                        | Current limitation                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Static type safety                          | The project remains JavaScript. There is no TypeScript compiler or end-to-end compile-time request/response typing. Runtime validation covers the public Rook boundary, not every internal value.                                                                                                                                                            |
| Browser behavior and accessibility coverage | Existing source/API tests and bundle checks are not a complete React browser integration suite. The browser tool blocked the local preview reload during this refactor, so interactive desktop/mobile, focus, swipe, motion and WebGL checks remain unverified here.                                                                                         |
| Real-world performance                      | The new budget measures delivered JavaScript, including startup motion features. It is not an LCP/INP/CLS or device CPU benchmark.                                                                                                                                                                                                                           |
| Optional 3D engine                          | Vendored Three.js is still approximately 664 kB minified. It remains deferred and still triggers the unchanged Vite warning. The engine was not replaced or rebuilt as a smaller package.                                                                                                                                                                    |
| Procedural scene code                       | WebGL lifecycle and world construction are separated, but the retained world builder is still a sizeable procedural implementation with short geometry variable names. A deeper geometry/controller redesign is not claimed.                                                                                                                                 |
| Full design-token consistency               | Feature styles are colocated and dialog primitives shared. The existing global styled-components theme, literal colors and some design-era CSS class names remain. There is no complete token-only styling policy.                                                                                                                                           |
| Dependency audit                            | The current Firebase dependency tree reports four high-severity audit entries through its unused Firestore/gRPC subtree. Only app/analytics modules are imported by the portfolio; that does not make the installed dependency audit clean. A compatible update did not clear the advisories; no forced major downgrade or unsupported override was applied. |
| Distributed backend limits                  | Request/concurrency limits are per handler instance. There is no shared rate-limit store, identity system or distributed quota accounting.                                                                                                                                                                                                                   |
| Schema generation                           | The API contract and constants are documented/shared, but there is no generated OpenAPI specification or runtime schema library.                                                                                                                                                                                                                             |
| End-to-end delivery                         | Mocked provider and contact-service code checks do not verify real credentials, production hosting, external provider availability or email delivery.                                                                                                                                                                                                        |

The goal is a maintainable, explicit architecture with measurable gates. Remaining work should address these specific gaps, rather than adding layers or abstractions solely to make the repository appear more elaborate.
